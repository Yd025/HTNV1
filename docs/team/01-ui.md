# Person 1 — Interface and demo

Enhance the existing Operation Overwatch interface so judges can distinguish a measured target from a prediction, understand handoffs, and see real results. The frontend already exists: Next.js 14 Pages Router, Tailwind, a 3D `TacticalScene`, a 2D `TacticalMap`, live telemetry, a camera rail, and a contact panel. Build on it.

Read [AGENTS.md](../../AGENTS.md), [the team contract](CONTRACT.md), and [the Git workflow](GIT_WORKFLOW.md). The existing `SwarmState` in [frontend/lib/types.ts](../../frontend/lib/types.ts) is the current frontend contract; proposed additions require Person 2's agreement.

## Ownership and local setup

**Branch:** `codex/ui`. **Own:** `frontend/**`, including its package manifest and lockfile. Coordinate `frontend/lib/types.ts` with Person 2 before editing shared fields. Preserve `frontend/lib/geo.ts` and the existing WebSocket transport. Do not change backend code or introduce another frontend framework.

In your own clone, track the team's published branch:

```powershell
git fetch origin
git switch --track origin/codex/ui
```

If already checked out locally, use `git switch codex/ui`. Update from `dev` and submit pull requests back to `dev` as described in the Git workflow.

For an integration backend, from the repository root in one terminal:

```powershell
$env:ADAPTER = 'local'
$env:FORCE_KINEMATIC = '1'
docker compose up --build backend
```

This starts the backend and its database dependency. In another terminal, from the repository root:

```powershell
cd frontend
npm ci
npm run dev
```

Open `http://localhost:3000`. Defaults already target `http://localhost:8000` and `ws://localhost:8000/ws/telemetry`. If Person 2 changes the host port, set `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_WS_URL` accordingly before starting Next.js. These public values contain connection URLs only; keep sponsor keys out of the browser. Do not also start the Docker frontend on port 3000.

## First deliverable

Keep both existing views, role displays, heatmap, and four score tiles. Improve their hierarchy and make missing data explicit. Preserve the label **“Stand-in arena · not Dominion terrain.”** The local kinematic target is synthetic; a working WebSocket does not establish live WHITEOUT perception.

Prioritize these improvements:

1. Improve the existing contact panel using available `TrackState` fields and detection reports. Track fields include latitude/longitude, velocity, confidence, `age_s`, and scalar `sigma_m`. Confirm semantics in the contract; do not assume age means time since the last accepted observation.
2. With Person 2, add explicit measured/predicted/lost state and observation freshness to the shared payload. Until supplied, show freshness/status as unavailable. Do not infer visual contact from connection state or confidence.
3. Display estimated uncertainty using the actual available representation. A scalar sigma is not a full covariance ellipse. Add an oriented ellipse only after the backend provides a documented covariance and coordinate convention. Avoid an unsupported “95%” label.
4. Make C2 intent, blackboard traffic, and advisor rationale readable. Distinguish planned tasking from confirmed handoff; request outcome/evidence fields from Person 2 where absent.
5. Show missing scores and unavailable truth-based error as “Unavailable,” not zero. Clearly mark disconnected data as stale while retaining the last received state.

## Integration boundaries

Keep `/ws/telemetry` as the mission-state stream. Existing HTTP routes are `/health`, `/telemetry/latest`, `/cameras`, and `/cameras/{cam_id}/snapshot.jpg`; follow their actual response shapes. Do not introduce `/api/state`, a new mission polling service, or direct simulator access.

Reuse the existing camera rail and backend snapshot proxy. Improve camera discovery using `/cameras` rather than assuming every camera exists. An empty catalogue is expected for the local adapter. A snapshot may return `204` when no frame is available; show a clear unavailable state and bounded refresh behavior instead of a broken image or stale image presented as fresh. A missing image or detection does not establish that the water is empty or that a tower is scanning.

Reuse latitude/longitude inputs and existing geographic conversions: local north/east becomes Three.js east/up/minus-north. Keep Leaflet and R3F dynamically loaded with SSR disabled. The interface must not invent contacts or issue arbitrary flight commands.
